Governed Seed Kernel for Agent Evolution

Agent_X is a minimal L0 foundation for building agents safely: stable entrypoint, strict contracts, governance-before-action, traceability, replay, checkpointing, and evidence-producing proofs. It is not a finished assistant; it is the governed seed layer that an external AI, coding agent, or orchestrator can evolve into specialized agents, controllers, or swarm systems.

Why Agent_X

The Problem with
Ungoverned Agents

Most agent projects begin as ad hoc tool chains. Agent_X starts from the opposite direction: a small governed kernel whose boundaries, proofs, artifacts, and extension rules are explicit from the first turn.

Unsafe Runtime Mutation

Production mode rejects live self-modification and promotion from normal turn execution, keeping the seed stable while evolution happens outside L0.

Governance Gaps

Planner output must pass governance before the gateway executes. Direct shell, network, and unapproved filesystem writes are blocked in the default seed.

Weak Evidence

Agent_X treats traces, checkpoints, memory, evaluation, and proof results as first-class artifacts instead of informal claims about what happened.

Core Concepts

How Agent_X Works

Agent_X keeps L0 small and evidence-focused. New capability belongs in an outer layer or behind governed extension/profile boundaries.

L0 Seed Runtime

A minimal bootable kernel with one governed execution path, strict request/response contracts, and no dependency on GPU, model, Docker, secrets, or network access.

External Evolution Loop

A human, coding agent, or orchestrator proposes the smallest safe repository change, runs proof commands, and records actual evidence before the next step.

Authority Documents

Seed invariants, capability manifest, extension ABI, acceptance checklists, and public contract policy define what may change and what must remain stable.

Proof-Gated Change

Canonical proof commands verify boot, governed turns, governance denial, gateway ordering, evidence persistence, checkpoint replay, manifest closure, and phase alignment.

Architecture

Governance-First
Execution Path

Agent_X routes every seed turn through a narrow, inspectable path. The planner selects an intended tool, governance decides whether it is allowed, and the gateway becomes the only execution choke point.

Example

Seed Runtime Commands

Run the seed, prove the governed execution path, and clean generated artifacts with a compact Makefile workflow.

quick-start.sh 
# Clone Agent_X
git clone https://github.com/Astrocytech/Agent_X.git
cd Agent_X

# Install minimal seed dependencies
make install

# Compile and boot the governed seed
make seed-boot

# Run canonical L0 proof suite
make prove-seed

# Execute one default governed seed turn
make run

# Remove generated runtime artifacts
make clean
